# Direct input reads in girth-five graph circuits

L-meta-606 asks for a universal constant `k` such that `|E(G)| ≤ k(s + 1)` whenever a monotone AND/OR circuit of size `s` and fan-in at most two computes the edge function of a finite simple graph of girth at least five. The edge function accepts a set of vertices exactly when it contains both endpoints of an edge. The universal linear bound remains open.

## Checked results

- **It suffices to consider minimum circuits with few direct reads.** Fix a proposed coefficient `k`. For a vertex `v`, let `r(v)` count the distinct gates whose input list contains its raw input wire. The bound for all circuits is equivalent, with the same `k`, to the bound for minimum circuits satisfying `k r(v) < deg(v)` at every nonisolated vertex. Pinning `v` to false deletes its incident edges and saves at least `r(v)` gates. When `deg(v) ≤ k r(v)`, induction transfers this saving back to the original graph. [Weighted pinning](src/WeightedPin.lean) · [Fixed-coefficient equivalence](src/ReaderCore.lean) · [Minimum circuits](src/MinimalCore.lean)

- **Blocking sensitivity costs exactly the degree.** Fix `v` and prescribe other coordinates to be true or false, with disjoint prescriptions and with the true vertices forming an independent set. The minimum number of prescribed coordinates that prevent every completion where toggling `v` changes the edge function is `deg(v)`. Fixing all neighbors to false attains the bound. [Completion lemma](src/Sensitivity.lean) · [Exact minimum](src/CertificateSize.lean)

- **A sole binary reader needs more than a second raw input.** If `deg(v) ≥ 2` and only one gate reads `v`, that gate cannot have exactly `v` and another raw input as its operands. More generally, when all readers of `v` have distinct-from-`v` raw partners and the number of distinct partners is below `deg(v)`, either a partner occurs at both an OR and an AND reader, or two OR partners are adjacent. Two distinct vertices, at least one of degree two or more, must also differ in which gates read them. [Raw partners](src/RawPartners.lean) · [Distinguishing readers](src/TwinReaderBarrier.lean)

- **The prefix before a sole reader is constrained.** A sole AND reader's partner is true on each neighboring singleton. In a minimum circuit the partner is false on the empty input, so all neighbors are essential for the partner and `deg(v) ≤ prefix.length + 1`. For a sole OR reader, either the same prefix-size bound holds or, on every assignment with `v = false`, the partner fires only if the assignment already contains an edge. The hypotheses on the gate's operands, uses and output appear in the Lean statements. [Prefix bounds](src/DegreePartner.lean) · [Removing a copied wire](src/MinimalPartner.lean) · [Essential inputs](src/Support.lean)

- **A short prefix permits a same-size relocation.** In a minimum circuit satisfying the direct-read condition above, take `k > 0` and a nonisolated vertex of degree at most `2k`. Its unique reader combines its raw input with a wire already computed in the prefix. If `prefix.length + 1 < deg(v)`, the reader is an OR and whenever the partner fires, the graph function accepts. One can bypass that reader and move its partner to a final OR, preserving the function and the exact gate count. [Reader and wire location](src/ReaderShape.lean) · [Global implication](src/CleanSignal.lean) · [Circuit construction](src/CleanOr.lean) · [Graph-specific relocation](src/CleanGraphMove.lean)

The graph estimates also bound the size of a possible counterexample. A violation of coefficient `r + d` has an induced restriction that still violates `r`, in which every nonisolated vertex has degree greater than `d` and the circuit has more than `4r²` gates. [Core extraction](src/CounterexampleCore.lean) · [Moore bound](src/Moore.lean)

## Build

Prepare a checkout of the proof repository, with Lean `leanprover/lean4:v4.36.0` and the pinned mathlib revision `fc4f59e577feb1a4956671bc04ac18aaaf8cd842`. In its `lean` directory run `lake exe cache get` and `lake build PEqualNP.Defs`. The clean local build uses upstream `2e67c7c`. The builder also accepts `f0a159a`. Its toolchain, manifest and L-meta-1708 source are identical. The latter revision adds the independent TwoColour definitions to the definitions root. [Reproduction revision](https://github.com/open-goat/pequalnp-proofs/tree/2e67c7c8499e2e12d39c1f31c085c0e4e94b0391) · [Later revision](https://github.com/open-goat/pequalnp-proofs/tree/f0a159afb752cd39530ed7e78e7d427dbbd1d854)

From this companion directory, run the following command with Python 3.9 or later, Git and an empty output directory outside the upstream checkout and companion.

```sh
python build.py --upstream /path/to/pequalnp-proofs/lean --build-dir /path/to/empty-build
```

The builder reads L-meta-1708 directly from the pinned checkout at `lean/PEqualNP/Outside/L_meta_1708.lean` and compiles it as a flat module. The corresponding import in WeightedPin uses that flat filename. The theorem retains the name `PEqualNP.Outside.L_meta_1708`. The builder compiles the other sources in dependency order, imports the results in a fresh Lean process and rejects any audited theorem using an axiom outside `propext`, `Classical.choice` and `Quot.sound`. To build one target, append `--target MinimalCore:Edge606.ReaderCore.fixed_coefficient_minimal`. Use `--lean /path/to/lean` for a release binary installed outside elan. [Build script](build.py)
